# AI Tycoon Hub 文件入口

先讀正式規範，再依需求查看原型。本頁只整理來源界線、現有差異與待決事項，不另定一套 Hub 佈局。

## 來源與角色

| 檔案 | 用途 |
|---|---|
| [UI 佈局與 RWD 行為規範](AI-Tycoon-Hub-UI佈局與RWD行為規範.md) | Hub 正式規範；版本見文件開頭。佈局、資訊上限、狀態延續與 UX 驗收以此為據。 |
| [互動參考原型](AI-Tycoon-Hub.html) | 保存上傳的 `AI-Tycoon-Hub (1).html`。只參照浮動 UI，不是產品實作或驗收報告。 |
| [共用規範](../../SPEC.md) 與 [token 索引](../../tokens/index.json) | 共用設計要求、數值與引用。Hub 不自行取代全域 token。 |

兩份來源檔保留既有路徑與內容。正式規範第 10 節的「本對話」指向此次匯入的定稿來源，不要求 Agent 取得對話紀錄才能執行規範。其 `outputs/ai-tycoon-hub/dist/index.html` 是原始環境路徑，不是倉庫內建置目標；倉庫可用副本是本頁連結的 HTML。外部預覽網址只是補充，不是驗收所需的唯一入口。

原型內「Grid v1.4／已鎖定」及城市相關敘述屬參考檔原文，不代表正式規範已確認所有內容。系統發布版本、規範版本與原型版本分開維護。

## 既有來源對照

以下是整合時的差異記錄；右欄說明如何避免把參考資料當成新要求。正式條款仍回到連結的來源查閱。

| 議題 | 來源中的差異 | 使用界線 |
|---|---|---|
| 模式與斷點 | Hub 規範第 5.1 節記錄原型以 `landscape` 且 `36rem` 切換；全域寬度帶由 `layout.breakpoint` 決定。 | Hub 模式不等於 `sm`。不把全域 `sm` 改成原型門檻，也不把 `sm` 直接當成 Hub 橫屏條件；產品映射見 HUB-OPEN-01。 |
| 浮動 UI 與一般正文 | Hub 規範第 2.1 節要求城市底圖在下、UI 在上；共用規範第 3 節要求固定層不遮住操作。 | 防遮擋約束作用於操作入口，不把城市底圖推成正文欄，也不據此推定城市地圖尺寸。 |
| 格線與間距 | 原型使用自訂軌道、比例、`clamp()` 與內嵌 CSS；共用規範第 3–5 節使用語意 token。 | 參考浮動區域位置，不直接把原型的 CSS 常數當成已核定 token；產品格線與間距映射見 HUB-OPEN-02。 |
| 短高度與入口 | 共用規範第 2 節會收納次要操作；Hub 規範第 2.3、6 節要求必要入口可達並允許必要垂直捲動。 | 不以維持一屏為由移除主要導覽、資源或任務操作。是否需要收納，以正式需求與可達性驗證判斷。 |
| 對話框 | 原型保留居中圓角面板；共用規範第 3 節對 `base`／短高度另有全螢幕要求。 | 原型外觀不是豁免；產品依共用契約處理，仍保留 Hub 要求的輸入、閱讀位置與返回入口。 |
| 動效 | 原型採 380ms 位移重排；共用規範第 9 節限定結構切換使用 `instant`／`fast`。 | 不把原型時長與位移升格為產品要求，也不改動既有 `motion` token 迎合原型。 |
| 色彩、尺寸與層級 | 原型有自訂色碼、尺寸及 `z-index`；共用規範第 4、6、9 節使用命名 token。 | 原型不代表已通過共用 token、對比與層級檢查；正式 UI 必須映射並驗證。 |
| 城市與建築 | 原型展示七棟、2–3–2 排列及具名入口；正式規範開頭明確排除其數量、名稱、位置、互動與城市 RWD。 | 只確認底圖在下、浮動 UI 在上的關係；其餘不得從原型反推。 |

決策後修改負責該議題的正式來源，並在此更新狀態與連結；不把本頁變成另一份平行規範。

## 驗收與驗證界線

UX 情境與覆蓋範圍只維護在正式規範第 8 節，不在本頁複製驗收清單。文件收錄與靜態檢查不能證明 UX-01 至 UX-14 通過。發布前仍需依正式條件驗證目標手機瀏覽器、工具列、安全區、鍵盤、旋轉、焦點與內容放大。
